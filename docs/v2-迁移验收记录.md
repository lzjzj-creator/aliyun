## 超出原清单的部分（多实例前置，Issue #3/#17 要求）

`20261118_v2_quota.sql` + 段落 9（32 条断言）在真数据库上验证了跨实例配额语义：

- 滚动窗口计数：`v2_spend_quota` 达到上限即拒绝并返回窗口剩余 `retry_after`（实测触顶返回 17 秒）；`ip`/`anon` 两个 scope 独立；**20 并发抢 `limit=10` 恰好 10 放行 / 10 拒绝，`hits=10` 无计数丢失**。
- 会话流租约：同会话第二个持有者被拒、同令牌可续约、非持有者不能释放、`ttl>900` 与非十六进制令牌被拒、过期租约可被抢占；**10 并发抢同一会话恰好 1 个持有者**；删除会话级联回收租约（不会留下把会话锁死的死租约）。
- 日 token 预算：到顶后拒绝、被拒支出不入账、超预算请求既不放行也不入账；**20 并发 50-token 支出恰好放行到预算线（剩余 400 时放行 8 次，`used=461≤500`）**，全局闸门成立。
- `v2_prune_quota` 只回收 7 天前的窗口与已过期租约，在用窗口/在跑租约保留；段落 9b 用 `20261118_v2_cleanup_schedule.sql` 中 `cron.schedule` 实际注册的同一条语句复跑两次，验证重复触发安全且第二次收敛为 0。

## 未覆盖项（如实记录，上线前必须补）

1. **pgvector**：EDB 便携版不含该扩展，v1 的 `match_chunks` 向量检索函数不在本脚本范围内。属 Supabase 环境项，需在真实 Supabase 项目里按同口径复跑（该库已有 v1 向量表）。
2. **不是线上迁移记录**：生产 Supabase 项目至今未应用任何 v2 DDL，`chat_sessions`/`chat_messages`/`user_profiles`/`v2_*` 均不存在，因此线上 `/api/v2/*` 仍为 404。执行需要项目凭证（`api.supabase.com` PAT 或由使用者在 SQL Editor 粘贴）与明确授权。
3. **pg_cron**：隔离实例未安装该扩展，定时器只做「语句级模拟」。线上需注册 `cron.job` 并在次日读 `cron.job_run_details` 确认 `status='success'`，这一步没有替代证据。
4. **手工角色 ≠ 完整 Supabase 运行时**：脚本创建的 `anon`/`authenticated`/`service_role` 用于权限断言足够，但真实项目的 PostgREST 网关、`pgrst` 重载、默认权限继承等仍需线上冒烟确认。

## 与部署的关系

验收通过是开开关的必要条件之一，不是充分条件。`V2_MEMORY_ENABLED` / `COACH_ENABLED` / `V2_SHARED_QUOTA` 默认仍为 `0`，
线上开启顺序与回滚步骤见 `docs/部署清单.md`「v2 上线顺序」；合并 `main` 与部署 FC 是两件独立的事，都不等于验收。
