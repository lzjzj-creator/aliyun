# 协作开发流程（Devin 编排 × Qoder 开发）

> 本项目开发遵循"Qoder 主开发、AI 审查把关"的分工制度。
> 所有功能代码由 Qoder 编写；Devin 负责任务拆解、代码审查、测试验收与部署编排。

## 分工

| 角色 | 职责 |
|---|---|
| Qoder (qodercn CLI) | 唯一代码作者：新功能、修改、项目文档 |
| Devin | 任务卡设计（上下文/契约/验收标准）、git diff 审查、冒烟测试、部署执行、commit 推送 |

> 部署类长时盯守操作由 Devin 执行：一次性 qoder 会话结束后台进程会被带走。
| 项目负责人 | 账号授权、里程碑验收 |

## 标准循环

1. Devin 写任务卡：背景 + 涉及文件 + 接口契约 + 验收标准 + 边界（不 commit、不动密钥）
2. 派发：`qodercn -p "<任务卡>" --permission-mode bypass_permissions`（工作目录 D:\阿里云）
3. Qoder 开发并自测（要求跑 build/test）
4. Devin 审查：`git diff` + 契约检查 + 冒烟回归
5. 通过 → Devin 提交（commit 标注 [Qoder开发/Devin审查]）；不过 → 附评语派发返工

## 审查关卡（每个任务卡必过）

- 契约：前后端字段/事件名一致（route/sources/guide/token/done；analyze 嵌套结构）
- 红线：建议数字必须可溯源（_guard_fabricated_numbers）、密钥不进前端不进仓库
- 回归：/api/route 六用例、/health、RAG 端到端
- 范围：只改任务卡声明的文件

## 密钥纪律

- 服务密钥仅存 `D:\阿里云\.env`（已 gitignore）
- 部署脚本现场读 .env 构造参数，不写明文进文件/日志/会话
- 前端只拿 VITE_API_BASE / VITE_ANALYZE_URL 两个公网地址

## v2 起：两人 × 各自 agent 协作（2026-11-16 补充）

v1 的"Qoder 单作者 + Devin 审查"模式在 v2 变为**两人全栈 + 各自 agent**。以下规则取代上文的单人条款（v1 历史记录保留备查）：

- **任务源**：GitHub Issues（`docs/知脉-v2-issues.md`），分工与契约见 `docs/知脉-v2-开发计划.md` §12。
- **分工**：P0 共享件期 A 做后端件、B 做前端件；其后纵向分域——A=访谈引擎域、B=简历向导域，各自端到端。
- **审查与合并**：一 issue 一 PR，互为审查人；审查人修改直接在 PR 分支推 `[审查]` commit 再合并，不本地暗改。
- **agent 交接**：任务上下文 = issue 正文（派发时粘贴）；规则变更 = 更新本文档/开发计划；触达对方 = issue/PR 评论 @。**不发邮件**。
- **契约纪律**：SSE 协议/session API 归 A 监护，模板契约归 B 监护；变更须评论 + 同步 `demo/v2` fixture。
