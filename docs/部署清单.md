# 部署清单（单人操作版）

目标架构：Qoder Sites（前端静态）→ CloudBase 云托管（两个后端）→ Supabase（数据）

## 一、部署后端 ×2（CloudBase 云托管）

前置：`npm i -g @cloudbase/cli`，然后 `tcb login`（浏览器微信授权）。

### 服务1：zhimai-api（FastAPI 主后端）

```bash
cd D:\阿里云\backend
# 构建镜像（需要 Docker Desktop 运行中）
tcb cloudrun deploy --source . --service zhimai-api --envId <你的环境ID> --port 80
```

环境变量（控制台 → 云托管 → zhimai-api → 配置，或 `tcb cloudrun deploy --env`）：
```
SUPABASE_URL=https://wtejkttvdzqbalkdfnhp.supabase.co
SUPABASE_SERVICE_KEY=<service_role key>
DASHSCOPE_API_KEY=<百炼key>
DEEPSEEK_API_KEY=<deepseek key>          # 兜底用，可选
ALLOWED_ORIGINS=https://<sites域名>,http://localhost:5173
QWEN_MODEL_CHAT=qwen-plus
EMBEDDING_MODEL=text-embedding-v4
MIN_RETRIEVE_SCORE=0.25
```

### 服务2：resume-analyze（简历诊断，复用源码）

```bash
cd D:\阿里云\vendor-resume-audit\api
tcb cloudrun deploy --source . --service resume-analyze --envId <你的环境ID> --port 3000
```

环境变量：
```
DEEPSEEK_API_KEY=<deepseek key>
ALLOWED_ORIGINS=https://<sites域名>
```

部署成功后各得到一个 `https://<env>-<app>.tcloudbase.com` 域名。

## 二、部署前端（Qoder Sites）

```bash
cd D:\阿里云\frontend
# 1. 把后端地址写进构建环境变量
echo "VITE_API_BASE=https://<zhimai-api域名>" > .env.production
echo "VITE_ANALYZE_URL=https://<resume-analyze域名>/api/analyze" >> .env.production
# 2. 构建
npm run build
# 3. 用 qodercn 发布 dist/ 到 Sites（CLI 交互式引导首次登录）
qodercn
# 或在 Qoder IDE 里：右键 dist/ → Deploy to Sites
```

发布后把 Sites 域名回填到两个后端的 `ALLOWED_ORIGINS`，重启生效。

## 三、验证清单

- [ ] `curl https://<zhimai-api>/health` → `{"ok":true}`
- [ ] `curl https://<analyze>/health` → ok
- [ ] Sites 页面发一条知识库问题 → 流式回答 + 来源链接
- [ ] Sites 页面上传示例简历 → 诊断出报告
- [ ] 「示例演示」按钮走通（不烧配额）

## 故障速查

| 现象 | 原因 |
|---|---|
| 前端请求 CORS 报错 | 后端 ALLOWED_ORIGINS 没加 Sites 域名 |
| 问答无来源 | Supabase service key 配错/RPC 查空 |
| 改写全兜底 | DASHSCOPE_API_KEY 没注入容器 |
| analyze 502 | DEEPSEEK_API_KEY 缺失且 engine=deepseek |
