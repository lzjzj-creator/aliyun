
## 管理后台（#admin，密码保护）

公开站保持可评审；管理入口不放进导航，只通过隐藏地址进入：

```
https://zhimai-resume-uxvajmzewfe.qoder.zone/#admin
```

首次配置或改密码：

```bash
python ingest/make_admin_password.py            # 随机生成，写入本地 .env
python ingest/make_admin_password.py --rotate   # 换密码，同时让旧会话失效
bash deploy/deploy-fc.sh                        # 只把哈希和签名密钥下发 FC
```

- 密码只存在本地 `.env` 的 `ADMIN_PASSWORD`，不会打进前端包；线上校验 `ADMIN_PASSWORD_HASH`（PBKDF2-SHA256）
- 登录返回 HMAC 签名令牌，默认 2 小时过期，浏览器只存 sessionStorage；关标签页即退出
- 同一来源连续输错 5 次会暂停 5 分钟，避免公开接口被暴力尝试
- 管理接口：`POST /api/admin/login`、`GET /api/admin/overview`、`GET /api/admin/documents`
- 未配置哈希/密钥时管理登录返回 503，公开问答与知识库镜像不受影响
- 静态托管本身没有鉴权，密码关卡由 FC 后端承担；不要把管理页改成纯前端判断

## 故障速查

| 现象 | 原因 |
|---|---|
| CORS 报错 | ALLOWED_ORIGINS 没含 Sites 域名 → 改 .env 重跑 deploy-fc.sh |
| 首次请求慢 3-8s | FC 冷启动，正常 |
| 问答无来源 | Supabase key 失效/向量查询为空 |
| 来源 404 | 镜像未发布该文章，或 `KB_SOURCE_BASE`/`VITE_KB_SOURCE_BASE` 不一致 |
| 来源仍指向原站 | FC 的 `KB_SOURCE_BASE` 未注入，或前端构建没带 `VITE_KB_SOURCE_BASE` |
| 改写兜底文案 | DASHSCOPE_API_KEY 没注入或限流 |
| analyze 502 | DEEPSEEK_API_KEY 缺失且 engine=deepseek |
