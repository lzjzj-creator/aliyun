## 2. 产品（不变）

知脉·简历成长助手：问答 + 简历双入口，Decision Layer 意图路由串联，AI 不编造事实。

## 3. 单人架构（一个前端 + 两个后端 + 一个库）

```
Qoder Sites 静态前端（Vite SPA，双 Tab）
  ├─→ 服务1：自建 FastAPI（CloudBase 云托管 或 阿里云FC，D1 定）
  │     ├─ POST /api/route          Decision Layer：L1 关键词 → L3 qwen-turbo 分类
  │     ├─ POST /api/chat/stream    RAG：Supabase 检索 → qwen-plus → SSE 流式+来源
  │     └─ POST /api/resume/rewrite STAR 改写 + 缺数据反问（红线：不虚构）
  └─→ 服务2：vendor-resume-audit/api 原样重部署（Node）
        └─ POST /api/analyze        简历诊断（general/targeted，evidence_gaps）

Supabase：documents / chunks(embedding 1024维/visibility/kb_scope) / 可选 sessions
模型：百炼 qwen-turbo（分类）+ qwen-plus（生成），DeepSeek 兜底；embedding 用百炼 text-embedding-v4 或 SiliconFlow bge-m3
```

**为什么这么摆**：服务2零改动当天上线，服务1只有一个文件几个接口，Supabase 免运维——一个人也守得住。

## 4. 单人范围（砍过的，别贪）

**做**：双入口首页、问答（流式+来源+拒答+引导问题）、简历（上传/粘贴→诊断→事实确认→STAR改写→并列展示可复制）、Decision Layer（L1+L3）、脱敏示例、隐私声明条、错误/限流态。
**降级**：PDF 导出用浏览器打印代替精排；前后对比只做并列不做逐字 Diff；L2 语义路由缓建。
**不做**：注册登录、后台、版本管理、OCR、多 Agent、用户上传进库。
