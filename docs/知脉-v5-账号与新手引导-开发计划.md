## 1. 目标架构（单归属根模型）

```
浏览器仅存：auth_token（Authorization: Bearer）——guest 也算
                            │
Supabase：app_users (kind: guest | user)  ← 唯一归属根
   ├─ app_user_tokens.user_id（token 哈希表，吊销/过期）
   ├─ chat_sessions.user_id ─→ chat_messages / user_profiles
   ├─ v3_owner.user_id ──────→ v3_facts / v3_resume_documents
   ├─ resume_drafts.user_id ─→ 草稿 fields/evidence_map/照片（新表）
   ├─ init_profile（user 行 jsonb）
   └─ settings（user 行 jsonb，UI 偏好上云 → 真·零本地数据）
```

**整体废止**：`X-Anon-Id`/`X-Session-Token`/`X-Owner-Token` 三套头、每会话令牌签发与哈希校验、owner_token 与恢复码、认领事务、`zm_*`/`zhimai.*` 全部本地数据键。归属校验 = `user_id` 匹配一行；越权统一 404。

**两个代价（已确认接受）**：guest token 丢失 = 数据孤儿（注册后免疫）；旧测试数据作废。

### init_profile 的三个消费点

1. **访谈**：建会话时播种 `user_profiles.profile`——年级/学校/专业/求职意向不再是 gaps，ProfilePanel 那排"待补充"chips 从源头消失；
2. **简历**：autofill 前并入 `fields` 预填（basics/education 直接可用）；
3. **换设备**：数据跟 `user_id` 走，登录即全量可见。

## 2. 数据模型（`supabase/migrations/2026MMDD_v5_accounts.sql`）

```sql
create table public.app_users (
  id uuid primary key default gen_random_uuid(),
  kind text not null default 'guest' check (kind in ('guest','user')),
  username text unique,                      -- guest 为 null
  username_lc text unique,                   -- 小写归一防大小写重复
  password_hash text,                        -- scrypt$N$r$p$salt$hex；guest 为 null
  init_profile jsonb not null default '{}',
  settings jsonb not null default '{}',
  guide_seen_at timestamptz,
  created_at timestamptz not null default now(),
  last_login_at timestamptz,
  deleted_at timestamptz
);

create table public.app_user_tokens (
  token_hash text primary key check (length(token_hash) = 64),  -- sha256(auth_token)
  user_id uuid not null references public.app_users(id) on delete cascade,
  created_at timestamptz not null default now(),
  last_seen_at timestamptz not null default now(),
  expires_at timestamptz not null default now() + interval '90 days',
  revoked_at timestamptz
);

create table public.resume_drafts (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references public.app_users(id) on delete cascade,
  template_version text not null,
  title text not null default '未命名草稿',
  fields jsonb not null default '{}',
  evidence_map jsonb not null default '{}',
  gaps jsonb not null default '[]',
  photo jsonb,                               -- {data_url | asset_ref}
  updated_at timestamptz not null default now()
);
create index resume_drafts_user_idx on public.resume_drafts(user_id, updated_at desc);

alter table public.chat_sessions add column user_id uuid references public.app_users(id);
alter table public.v3_owner      add column user_id uuid references public.app_users(id);
create index chat_sessions_user_idx on public.chat_sessions(user_id) where user_id is not null;

-- 保留期机制停调度（函数与列保留不删，可逆）：
select cron.unschedule('zhimai_v2_message_prune');   -- 48h 消息清除
select cron.unschedule('zhimai_v2_session_cleanup'); -- 90 天会话清理（按实际 job 名）
select cron.unschedule('zhimai_v3_owner_retention'); -- 365 天 owner 保留（按实际 job 名）
```

全部 `enable row level security`、无 anon/authenticated policy，只走 service key（沿用 v3 口径）。密码用 **stdlib `hashlib.scrypt`**（N=2^14, r=8, p=1）+ `hmac.compare_digest`，零新依赖。

## 3. 接口契约（`/api/v4/*` 新接口 + v2/v3 存量改造，`V4_ACCOUNTS_ENABLED` 开关默认 0）

### 3.1 账号与归属（新）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v4/auth/guest` | 无声创建 guest 行 → `{auth_token}`；前端首启动无 token 自动调（幂等，每次发新 token） |
| POST | `/api/v4/auth/register` | `{username, password}` + Bearer<guest_token> → **升级同一行** → `{auth_token, user:{username, needs_init:true}}` |
| POST | `/api/v4/auth/login` | `{username, password}` → `{auth_token, user:{username, init_done}}` |
| POST | `/api/v4/auth/logout` | 吊销当前 token（其他设备不动） |
| GET | `/api/v4/me` | `{kind, username, init_done, guide_seen_at, counts:{sessions,facts,resumes,drafts}}` |
| PUT | `/api/v4/me/init` | `{init_profile}` → 幂等保存；必填缺失 422 + `issues[]` |
| PUT | `/api/v4/me/settings` | `{settings}` → UI 偏好上云 |
| POST | `/api/v4/me/guide-seen` | 教程播完打点 |
| DELETE | `/api/v4/me` | `{confirm:"DELETE_ACCOUNT"}` → 级联硬删 |

### 3.2 数据资产（新）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/PUT | `/api/v4/drafts` | 草稿列表 / 保存（3 秒防抖自动存，guest 可用） |
| GET/DELETE | `/api/v4/drafts/{id}` | 单草稿读写删 |
| POST | `/api/v3/facts/dialog` | `{message, history_tail?}` → `{reply, draft_facts:[{kind,slot_path,value,quote}]}`；待确认队列来源，落库走既有 `createFacts`（`source_type=manual`）；30 轮/天/owner |

### 3.3 存量接口改造

| 改动 | 说明 |
|---|---|
| v2/v3 鉴权统一 | `require_anon`/`require_owner`/`X-Owner-Token` → 解析 Bearer → `user_id` 匹配 `chat_sessions.user_id`/`v3_owner.user_id`，否则 404；限流 `check_anon` 改按 `user_id` 计桶 |
| `POST /api/v2/resume/autofill` 扩参 | `{session_ids: string[], include_facts?: bool}`——逐会话归属校验、多会话消息合并、并入 confirmed facts（含随手记），evidence 标 msg_id/fact_id；旧 `{session_id}`/`{messages}` 形状保留兼容 |
| `POST /api/v2/resume/expand`（新） | `{template_version, fields, session_ids?, jd?}` → 逐 entry 按 **STAR** 扩写为段落；KB 检索只补细节词不引字段外事实；`_guard_fabricated_numbers` 守数字；缺数据落占位符 |
| 保留期字段 | `history_expired` 恒 `false`、`retention_warning` 恒空（契约不破坏）；`memory.py` 的 48h 读过滤移除；过期横幅代码删除 |
| 通用口径 | `protocol:4`；错误 `{code,message,retryable}`；登录失败统一「用户名或密码不正确」；注册/登录 `enforce_ip` + 用户名维度限流（5 次/分，连续失败指数退避）；密码 ≥8，用户名 2–24（中/英/数字/`-_`） |

## 7. 隐私与安全（新叙事：从"什么都不留"到"都在你账号里，可查可删"）

- **隐私文案全面重写**：胶囊改「你的数据存在云端账号里，随时可删」；删除"48h 清除/只存本机/记忆默认关闭"全部表述；`#/memory` 同意弹窗改一次性告知条；`#/onboarding` 与软墙处加「初始化资料存于服务端并随账号删除」；README/PRODUCT.md 卖点更新。
- 密码只存 scrypt 哈希；token 只存 sha256；日志只记 user_id/username/耗时/错误码，**不记密码、token、init_profile/消息正文**（`test_privacy_hygiene` 全绿，48h 相关断言改为"不过滤但日志仍无正文"）。
- 删除账号 = 硬删 user 行级联全部资产（tokens/sessions/消息/画像/owner/事实/文档/草稿），UI 二次确认+文案明示；「不清除」只指不自动定时清，手动删会话/事实/文档/账号仍是硬删级联。
- 找回：无找回通道——注册/登录页写明「请牢记密码，暂无找回渠道」；guest 丢 token 同理不可恢复。
- 无自动清除后表持续增长——接受（用户量小）；`POST /api/admin/cleanup` 手动运维入口保留。
- 管理后台（P2 可选）：用户列表仅用户名/kind/注册时间/初始化状态/最近登录，不显密码哈希与 init 正文；复用 env 密码入口与 `admin_audit`。

## 8. 加载速度专项

> 病灶：`custom.debian10` 冷启动实测 7.7s（V3.1 §12.6），根因 460MB vendored Chromium 包 + 无保温 + 前端无预热 + 主 chunk ~910KB + 简历字体 2×10.7MB TTF。
> 方案：AWS `serverless-plugin-warmup`/`lambda-warmer` 保温模式 → FC3 原生 `timerTrigger`；拆函数瘦身 = serverless 单一职责惯例；前端 `defineAsyncComponent` + 动态 import + preconnect 标准组合。

| # | 项 | 做法 | 收益 |
|---|---|---|---|
| S1 | **FC 定时保温** | `s.yaml` 加 `timerTrigger`（`@every 5m`），`/health` 识别 warmup 早退（不跑业务） | 日常访客不再撞冷启动，成本≈0 |
| S2 | **前端预热 + preconnect** | `index.html` preconnect API 域；App onMounted 静默 `GET /health` | 点发送时后端已热 |
| S3 | **拆 zhimai-pdf 独立函数** | `resume_pdf.py`+vendor（Chromium/字体/playwright）拆为第三 FC 函数 | 主 API 7.7s → ~1–2s |
| S4 | **首包瘦身** | 视图 `defineAsyncComponent`；`exportPdf` 点击时 `import()` | 主 chunk ~910KB → ~200KB |
| S5 | **字体优化** | TTF 子集化 + woff2 + `font-display:swap` | 21MB → 数百 KB |
| S6 | **骨架屏** | 会话列表/画像面板/简历库首载骨架 | 体感提升 |

**顺序**：S1+S2 先行（当天见效，不依赖任何其他工作）→ S4+S5（纯前端一次发布）→ S3 单独部署窗口（动生产形态，回归 PDF）→ S6 随手做。备选：付费**预留实例**彻底消灭冷启动。
**验收**：保温后 `POST /api/v2/chat/stream` 首 step <300ms；冷启动占比 <10%；Lighthouse LCP <2.5s（4G）；简历页无 ≥1s 字体白屏。

## 10. Gate 与验收清单

- **G0 契约**：fixture 冻结，接口形状双方 ack；
- **G1 账号地基**：guest 自动签发 → 注册升级同一行（数据零迁移）→ 登录 → 任意设备凭 token 见全部数据；越权统一 404；密码哈希不出现在响应/日志；cron 三个清理任务确认停调度；
- **G2 初始化**：必填缺失 422 issues 精确到字段；新会话画像已含年级/学校/专业/求职意向，ProfilePanel gaps 不含此四项；autofill 预填生效；
- **G3 软墙与教程**：访客全流程无拦截；软墙 24h 一节流可关；教程跨设备只播一次；375px 不横向滚动；
- **G4 简历管线**：3 会话+事实多选 autofill 的 evidence_map 跨源（msg_id/fact_id）且 quote 100% 可回溯；expand 输出 STAR 段落且无编造数字（守卫断言）；优化页删除后 `npm run build` + 前端测试全绿；对话随手记确认后可检索；
- **G5 性能**：§8 验收口径全过（首 step <300ms / 冷启动占比 <10% / LCP <2.5s / 无字体白屏）；
- **G6 删除闭环**：DELETE_ACCOUNT 后账号/tokens/会话/owner/事实/文档/草稿零残留；
- **G7 回归**：`V4_ACCOUNTS_ENABLED=0` 全站回到现状；既有单测（后端 383、前端 101）全绿 + 新增测试通过（注册登录/重名/guest 升级/越权/级联删/init 校验/无自动清除/多源 evidence/STAR 守卫）。

## 11. 明确不做

- 不做邮箱/手机验证、找回密码、第三方登录、Supabase Auth、Cookie 会话；
- 不做 streak/XP/每日目标等游戏化、不做初始化闯关版；
- 不做旧测试数据迁移、不做认领/恢复码兼容桥；
- 不做自动清理任务的替代品（数据永久留存，手动删除除外）；
- 不改 SSE 协议、profile JSONB 形状、模板契约形状；
- 不做账号间数据共享/协作；
- 不抄多邻国素材/文案/代码（只迁移机制；实施时在 `docs/开源许可.md` 记录参考来源）。
