## 1. 一页纸结论

- **产品**：知脉 · 简历成长助手——"知识库问答 + AI 简历助手"双板块 Web 应用，统一入口由 **Decision Layer** 意图路由串联。
- **三个差异化卖点**（作品帖主线）：① 1945 篇真实笔记的数据壁垒；② 问答↔简历同场景闭环（诊断报告可引用知识库求职方法论）；③ 三层级联意图路由 + kb_scope 检索域收窄——真 multi-skill agent，不是两页硬拼。
- **架构**：Qoder Sites 静态托管 Vite SPA → CloudBase 上**扩展现有 FastAPI 服务**（加 `/api/route` 和 `/api/resume/*`）→ **Supabase(pgvector) 存知识库**；LLM = 百炼 Qwen 主力 + DeepSeek 兜底；Embedding = BGE-M3。
- **简历管线**：解析→五维诊断（复用 A 的 `/api/analyze` 引擎与 evidence_gaps 模型）→STAR 改写（不虚构红线）→JD 匹配→PDF 模板导出（已确定做，砍单顺序兜底）。
- **关键前置**：D1 确认队友 CloudBase 服务 503 原因 + 摸清 Supabase chunks 表现状 + 申请百炼 key。

## 4. V1 功能清单

### 板块 A：知识问答
- RAG 检索（向量+关键词混合，Supabase pgvector）→ 流式回答 → 来源卡片（目录/文件名/片段/更新时间）
- kb_scope 检索域收窄（freshman/sophomore_junior/senior/cases/major/video）
- 无依据拒答 + 建议问法；首屏 6–8 个引导问题；多轮追问指代消解（P1）
- 识别到 resume_edit 意图 → 引导卡一键跳简历页（决策层联动，**闭环卖点**）

### 板块 B：简历助手
- 上传 TXT/DOCX/文字PDF 或粘贴 → 结构化 JSON（教育/实习/项目/技能分段）→ 提取结果可人工核对
- 五维诊断报告（结构/量化STAR/ATS兼容/动词强度/篇幅，anchored rubric 0-5 分）+ 雷达图 + 逐条问题 + 待补充事实反问
- **STAR 逐条改写**（动词开头、≥1 量化点、≤3 行；缺数据生成反问项，严禁虚构）
- 前后对比逐条 accept/reject（P1）；JD 匹配（覆盖率/差距/定制建议）；**PDF 模板精排导出** + Markdown 复制
- 诊断报告可引用知识库方法论条目（kb_refs，两板块化学反应）

### Decision Layer（技术亮点）
L1 规则快通道（强关键词/带附件→直路由，0 成本）→ L2 bge-m3 语义路由（top1≥0.72 且 margin≥0.08）→ L3 qwen-turbo JSON 分类（confidence<0.6 → 反问澄清）。输出 `intent/kb_scope/confidence/route_layer/action`。50–80 条评测集，目标准确率 ≥92%，分层命中率本身是作品帖素材。

### 不做（V1 明确排除）
注册登录、管理后台、版本管理、OCR、用户上传进知识库、多 Agent 编排、招聘站爬取。

## 5. 统一架构

```
浏览器（Vite SPA on Qoder Sites，静态）
  │ HTTPS + CORS
  ▼
CloudBase FastAPI（在队友 knowledge-rag 服务上扩展）
  ├─ /api/public/chat(/stream)     已有：问答
  ├─ /api/route                    新增：Decision Layer（L1规则→L2语义→L3 qwen-turbo）
  ├─ /api/resume/parse             新增：文件/文本→结构化 JSON
  ├─ /api/resume/diagnose          复用 A 的 analyze 引擎（rules+deepseek，evidence_gaps 模型）
  ├─ /api/resume/rewrite           新增：STAR 改写（SSE）+ needs_user_data 反问
  ├─ /api/resume/jd-match          新增（A 的 targeted 模式可打底）
  └─ /api/resume/export            新增：模板→PDF（weasyprint/headless；兜底 window.print）
        │
        ├─ Supabase Postgres+pgvector：chunks(embedding/visibility/status/kb_scope)
        ├─ 百炼 Qwen（DashScope 兼容接口）：qwen-turbo 分类 / qwen-plus 生成
        └─ DeepSeek / BGE-M3（SiliconFlow）：兜底 / embedding（沿用现有）
```

- **密钥**：DASHSCOPE_API_KEY、SUPABASE_*、DeepSeek key 全在 CloudBase 环境变量；前端零密钥。
- **降级**：FastAPI 服务救不活 → 原仓库镜像重新部署 CloudBase 服务（容器在则恢复快）；再不行 Sites Server Functions 托底（Pro 档有函数能力，已核实存在）。
- **隐私**：简历不落库、会话隔离、日志只记 hash/token 数、页面固定隐私声明条、示例全脱敏。

## 6. 接口契约

问答沿用现有 `/api/public/chat/stream`（SSE，待核实字段）；简历五接口按用户方案的 JSON Schema（basics/education/internships/projects/skills + DiagReport/MatchReport）；错误形状沿用 A 的 `{ok:false,error:{code,message}}`；限流沿用 3 次/24h/来源（注明非全局配额）+ 示例快照模式防评委被限流卡住。
