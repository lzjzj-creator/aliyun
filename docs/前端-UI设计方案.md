# 知脉 前端 UI 设计方案（v2）

> 调研日期：2026-11-18 ｜ 范围：`frontend/` 全部界面 ｜ 约束：纯 CSS、不引 UI 组件库、hash 路由、契约驱动渲染（开发计划 §0.1 选型总则不变）

## 1. 调研：同类产品怎么做

### 1.1 简历编辑器（第二、三步的主参照）

| 产品 | 结构 | 值得抄的点 |
|---|---|---|
| **超级简历 WonderCV** | 左模块列表（拖拽排序）→ 中间点击即编辑 → 右属性面板 | 「智能一页」自动压缩到一页；**检查面板**逐条列优化项、一键修复——直接对应我们的 `gaps`/`needs_input`/`pending_questions` |
| **Reactive Resume**（开源，MIT） | Builder 三栏工作站：左=内容区块编辑，中=实时预览画布（缩放/平移），右=排版与 ATS 检查；顶部 Write/Design/Check 三模式 | 「预览是工作台中心，表单是属性面板」的层级关系；autosave + 本地恢复（我们即改即存 localStorage 同思路） |
| **OpenResume / xitanggg**（开源） | 单栏 A4 预览即编辑器 | 单栏 ATS 版式细节：bullet 统一 ·、日期右对齐灰、区段小标题全大写+细横线；隐私卖点「数据只在你浏览器」做成**页面明文标语**——我们「简历不落库」也该这么亮 |

### 1.2 AI 对话/访谈（第一步的主参照）

| 产品 | 形状 |

| ChatGPT / Claude | 思考过程=一条**可折叠窄行**（icon+「已思考 N 步」+箭头），默认收起；绝不是卡片 |
| Perplexity / Dify | 来源=消息下方的横排小卡片（序号+标题+域名）；agent 步骤=左侧竖向时间线 |
| 我们现状 | `ThinkingSteps` 已经是 details/summary 折叠 + 状态点 + kind pill，方向对，**保持、微调即可**，不重做 |

## 2. 现状诊断

**已经好的**：配色本身有辨识度——暖纸底 `#faf7f2` + 深青 `#14525a` + 柿橙 `#e0643a`，不是 AI 默认那套紫蓝渐变，**色板不动**。`ThinkingSteps` 的形状对、Wizard 左表右预览的骨架对。

**真正的问题在结构**：

1. **壳是博客不是工作台**：`max-width: 860px` 居中单列 + 顶部胶囊 tab。访谈页里画像面板（`ProfilePanel`）是消息流上方的一张横幅卡，会话列表靠抽屉——三样东西都在跟消息流抢同一列。
2. **简历向导的层级反了**：现在是「表单为主、预览为辅」；同类产品的共识是**预览（A4 纸）是视觉中心**，表单只是它的属性面板。打印导出的是纸，用户盯的应该是纸。
3. **隐私卖点埋着**：「简历不落库、对话可删」只在 `.privacy` 一行小灰字里。OpenResume 把它做成显性承诺，我们也该——这是差异化卖点不是免责条款。
4. **状态色散**：成功绿用了 `#0e8a16`，警告黄/占位橙散在各 scoped 样式里，没有统一语义层。

## 3. 设计原则（写给实现者的判断力）

- **纸的隐喻贯穿**：产品产出物是"一张纸简历"。纸=白、底=暖纸、笔=深青、印章=柿橙。任何新界面先问"它是纸、桌面、还是工具"。
- **AI 过程=系统日志**：step/思考/守卫的呈现要"朴素可信"——窄行、等宽感、状态点、可展开。不做卡片、不做彩色渐变、不做图标块。
- **占位是邀请不是错误**：`【待补充:x】` 用琥珀色虚线框 + 「点我补充」行为，禁止红色（红色只给真错误）。
- **一屏一个主按钮**：每屏只有一个实心 accent 主按钮（发送/一键填写/导出 PDF/采纳优化稿），其余全部 ghost。

## 4. 设计 token（增量，不换皮）

```css
:root {
  /* 现有（保留） */
  --ink:#1f2a2e; --teal:#14525a; --accent:#e0643a; --paper:#faf7f2; --line:#e5ddd2;
  /* 新增语义层 */
  --surface:#fff;            /* 纸/卡片 */
  --surface-warm:#f3eee6;    /* 次级面板（现 privacy 条、pp-bar 底色已是此值，收敛为变量）*/
  --good:#3d7a4f;            /* 守卫通过/达标/完成 */
  --warn:#b8860b;            /* 待补充占位（琥珀，不用红） */
  --warn-bg:#fdf6e3;         /* 占位底色 */
  --err:#b3402a;             /* 真错误（现 turn-error/dead-banner 文字色，收敛） */
  --mute:#9a9186;            /* 弱化文字（多处散写，收敛） */
  --radius:12px; --radius-sm:8px;
  /* 布局 */
  --col-side:240px; --col-panel:280px; --a4-ratio:1.414;
}
```

迁移动作：把 scoped 样式里散写的 `#0e8a16`/`#b3402a`/`#9a9186`/`#f3eee6`/`#7a6f63` 全部替换成变量——先 grep 一遍统一，这是后续一切的地基。

## 5. 界面详案

### 5.1 全局壳（App.vue）— 博客壳 → 工作台壳

```
┌────┬──────────────────────────────────────────┐
│ 知  │  顶部条：会话标题（中） + 「对话留存可删·简历只在本机」标语（右）│
├────┼──────────────────────────────────────────┤
│ 访  │                                          │
│ 谈  │            当前视图内容                     │
│ 简  │                                          │
│ 历  │                                          │
└────┴──────────────────────────────────────────┘
```

- 左：64px 窄图标栏（访谈 / 简历 / 管理），选中态=左缘 3px accent 竖条，悬停出 tooltip 文字。不用汉堡抽屉装导航——抽屉只留给会话列表。
- 顶部条只放：当前会话/文档标题 + 隐私标语一行小字（`--mute` 色，常态可见不折叠）。
- 内容区 `max-width` 放开到 1280px，居中；访谈页内部再分栏。
- 移动端：图标栏收成底部 tab bar（3 个一级入口，拇指可达）。

### 5.2 访谈页（InterviewView）— 三柱一输入

```
┌──────────┬──────────────────────────┬───────────┐
│ 会话列表   │ 消息流                    │ 画像面板    │
│ 240px    │  ·思考流窄行(折叠)          │ 280px     │
│ (可折叠)   │  ·气泡+来源卡+引导卡       │ 覆盖率环    │
│ 新建/删除  │                          │ 已收集chips │
│          │                          │ 待补充chips │
│          │                          │ (可点→发问) │
│          ├──────────────────────────┤           │
│          │ [建议回复chips]            │           │
│          │ 输入框(贴底,圆角,悬浮阴影)   │           │
└──────────┴──────────────────────────┴───────────┘
```

**ProfilePanel 改造**（改动最大的组件）：
- 从消息流上方的横幅卡 → 右栏常驻面板。覆盖率从横条升级为**环形**（纯 CSS `conic-gradient` + 中间百分比，约 40 行），下面分两组 chips：已收集（teal 描边）/待补充（warn 虚线）。
- **待补充 chip 可点击** → 往输入框填入引导句或直接 `send()`（学 WonderCV 检查面板的"一键修复"思路：面板不只展示状态，还提供行动）。
- 折叠行为：桌面端默认展开、可收成 48px 窄条（只露环）；移动端收成消息流上方一行 36px 摘要条（环缩小+百分比+「展开」）。

**ThinkingSteps 微调**（不重做）：
- running 步骤的脉冲点保留；每行高度收紧到 24–26px，detail 截断一行悬停看全文（现在 detail 会折行把行撑高）。
- 结束后 summary 文案「思考过程 · N 步」保持，hover 才变色——现在这个组件已经符合"系统日志"原则，只调密度。

**开场双入口**：招呼消息里的「开始访谈 / 直接提问」从普通 chips 升级为**两张等宽大按钮卡**（surface 底、teal 边、悬停 accent 边）——它是旅程入口，不是快捷回复。后续轮次的 `suggest_reply` 仍用小 chips，贴输入框上方而不是挂在消息体内。

**dead/错误**：dead-banner 现在样式对（暖橙底+err 字），保留；`turn-error` 里的「重试」按钮改小一号 ghost，别跟主按钮抢。

### 5.3 简历向导（ResumeWizardView）— 预览当主角

```
步骤条（①填写 ②编辑预览 ③优化导出）横条置顶，数字+连接线，可点回退
┌─────────────┬──────────────────────┬────────────┐
│ 区块列表      │  A4 预览画布(中心)     │ 上下文面板   │
│ 220px       │  白底·契约渲染·可缩放   │ 300px      │
│ 每区块一卡    │  ·待补充=琥珀虚线框     │ 步②=字段表单 │
│ ◇黄点=有占位  │  ·悬停=出处quote      │ 步③=优化进度  │
│ 点击→聚焦字段  │  点击字段→右栏定位     │   +改动对比   │
│             │  打印只渲染这一栏       │            │
└─────────────┴──────────────────────┴────────────┘
```

**核心改动**：
- **三栏化**：现在 `wiz-grid` 是 1fr/1.1fr 两栏。改 220px / 1fr / 300px 三栏，A4 预览占视觉中心（`aspect-ratio: 1/1.414`，默认缩放到适应宽度，可切 75%/100%）。预览用 `position: sticky` 已有，保留。
- **点击预览定位表单**：预览里每个字段区块 `data-field-path`，点击 → 右栏表单对应字段 `scrollIntoView` + 闪烁高亮（OpenResume/Reactive Resume 的"点击即编辑"）。
- **待补充占位**：`【待补充:x】` 渲染为 `warn` 琥珀虚线底框 + hover 显示「点击右栏补充」提示；evidence 悬停保留（现在已有），样式统一成纸质感 tooltip（surface 底 + line 边 + 小箭头）。
- **优化对比**：`compare` 模式从「同一张稿上标前后」改为**并排双稿**——左原稿右优化稿同滚动（scroll sync），改过的字段在优化稿上加 `--good` 左侧细条 + hover 出「原文 / 采纳此条」浮层。现在的 change_log 文本对比降级为下方可折叠明细。
- **步骤条**：从三个胶囊按钮改横向步骤指示器（①─②─③，完成步打勾、当前步 teal、未来步 mute），仍可点击回退。
- **导出**：右上固定实心 accent「导出 PDF」主按钮 + 旁边一行 `--mute` 小字「对话可删 · 简历只在你本机」。
- **步骤①收敛**：会话选择 + 一键填写是「准备动作」，做成居中窄卡（max-width 560px），不要占整屏两栏。

### 5.4 会话列表（SessionList）

- 访谈页左栏的一部分，不再是抽屉：会话卡=标题一行截断 + 时间 + stage 小字；选中态左缘 accent 条；底部固定「+ 新会话」。
- 删除仍是 hover 才露出的「…→删除」（防误触），二次确认用行内展开（「确认删除？删/取消」）不用弹窗。
- 移动端 = 全屏抽屉（现状不变）。

### 5.5 移动端规则（375px 验收线）

| 元素 | 行为 |
|---|---|
| 左图标栏 | → 底部 tab bar |
| 会话列表 | 全屏抽屉（现状） |
| 画像面板 | 消息流上方 36px 摘要条，点开上拉半屏 |
| Wizard 三栏 | 单列流：预览卡片在上（缩放 60%）→ 表单在下；导出按钮收进底部 sticky bar |
| 思考流 | 不变，本来就窄 |
| 来源卡 | 横滑一排，不换行 |
