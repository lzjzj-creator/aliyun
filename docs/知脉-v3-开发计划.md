# 知脉 · v3.0 开发计划 —— 长期记忆与岗位简历库

> 状态：**计划稿，未开工**（2026-11-19 起草）｜ 基线：`dev/v2`（v2 会话记忆 + 单会话 autofill 已可用）
> 一句话：把「用户在某一次会话里说过什么」升级为「用户这个人是谁」，并让这份长期事实按岗位产出多份简历。
> 本文只做方案与任务拆分，不含实现代码；末尾 §15 有 6 个必须由项目负责人拍板的问题。

## 0. 与 v2 的关系（先看这条）

v2 已经有**会话级**记忆：`chat_sessions` + `chat_messages` + `user_profiles`（profile JSONB + coverage），画像由每轮抽取写入，只活在这一个会话里。换一个会话，用户要重新讲一遍自己。

v3 要做的是**用户级**记忆与简历库：

```
v2 会话 A ──┐
v2 会话 B ──┼─→ 增量事实抽取 ─→ v3_facts（用户级长期事实，跨会话唯一事实源）
v2 会话 C ──┘                        │
                                     ├─→ 选岗位/贴 JD → 生成 → v3_resume_documents（后端/产品/算法 各一份）
                                     └─→ 每个字段仍可回溯到「哪次会话、哪句话」
```

**一条必须先说清楚的冲突**：v2 §3 明确写了「**简历不落库（已定）**」，简历字段只存前端 localStorage。v3 的「简历库」如果要做成「存多份、可管理、可跨会话复用」，就必须推翻这条，改为服务端存 `v3_resume_documents`。这不是顺手改的细节，涉及隐私文案、删除入口、90 天清理口径，**需要负责人明确拍板（§15 D1）**；拍板前 P0 数据层不动手。

与之配套的原则：v3 全程**不改变 v2 已有契约**（`/api/v2/*` 形状、SSE 事件、profile schema 都不动），新增 `/api/v3/*` 与独立开关 `V3_MEMORY_ENABLED`（默认 `0`）。关掉开关即回到 v2 行为，数据保留但不再新增。

## 1. 用户价值与验收故事

**故事 1（跨会话自动记得）**
用户在会话 1 说过「浙大计算机大三，做过校园二手书小程序、自己写后端、下单转化提升 30%」。三天后开新会话只说「帮我准备暑期实习」。教练直接引用这些事实追问「那段小程序的项目，QPS 压测做了吗」，而不是从零问「你什么专业、做过什么项目」。

**故事 2（一库多稿）**
用户在简历库新建两份：`后端开发-暑期实习`、`产品经理-校招`。两份共用同一批事实，但项目取舍、bullet 措辞、技能排序不同。改事实（比如补了一条新指标）后，两份简历各自提示「来源已更新」，由用户决定是否重新生成。

**故事 3（可查可删）**
用户在「我的记忆」里看到一条「GPA 3.8」标着来源会话《大三实习规划》第 12 条消息、原话「我 GPA 3.8，专业前 5%」。这条记错了，用户删掉；引用它的简历字段变成「来源已删除，请确认」，而不是悄悄保留错的。

**验收口径**：以上三个故事能在离线 fixture 上完整走通（不需要真模型），且第 3 个故事的删除链路上没有任何残留（导出包里也查不到）。

## 2. 审查结论与开工门槛

方向成立，但按现在 v2 的底座直接开工会挖出七个坑，先定掉再写代码：

| # | 门槛 | 不解决会怎样 |
|---|---|---|
| G-1 | **身份与授权**：跨会话事实库不能用 `anon_id` 当钥匙 | `anon_id` 是前端 `crypto.randomUUID()`，明文放 header，知道就能读写别人的全部人生事实；且清缓存即丢，长期资产变孤儿数据 |
| G-2 | **同意与可见性**：默认关闭 + 明示告知 + 随时可查可删 | 「把用户所有会话提到的个人信息汇总」是比会话更高的隐私等级，静默开启不可接受 |
| G-3 | **事实模型与冲突语义**：一条事实 = 原子值 + 来源证据 + 状态机 | 若存「模型生成的画像摘要」，就无法回答「这句是谁在哪说的」，也无法在用户纠正后精准替换 |
| G-4 | **简历落库口径**：存字段 + 证据引用 + 事实快照，不存模型自由文本 | 只存一段渲染后文本，等于放弃可编辑、可回溯、可重新生成 |
| G-5 | **删除与保留期**：事实级 / 来源级 / 全部，三级删除 + 导出 | 只做「删会话」会把事实留成无法追溯的幽灵 |
| G-6 | **成本闸门**：抽取是增量、异步、有日预算 | 全量重抽历史会话会把 token 预算一次烧穿 |
| G-7 | **兼容与回滚**：`/api/v3/*` 独立 + 开关默认关 + 新表独立 | 上线即改 v2 行为，出问题无法一键退回 |

## 3. 概念模型：四层记忆

| 层 | 载体 | 生命周期 | v3 是否新增 |
|---|---|---|---|
| L0 消息 | `chat_messages` | 会话级，90 天清理 | 已有 |
| L1 会话画像 | `user_profiles.profile` + coverage | 会话级，随会话删 | 已有 |
| L2 用户事实库 | `v3_facts` | 用户级，长期（保留期见 §9） | **新增** |
| L3 岗位简历库 | `v3_resume_documents` | 用户级，多份并存的文档 | **新增** |

分工原则：**L2 是唯一长期事实源，L3 只能从 L2 派生**。简历里任何一句话都要能落到「某条 fact → 某条 message → 用户原话」。不允许出现「只有简历里有、事实库查不到」的字段——那等于绕过了证据链。

## 4. 身份与授权

v2 的会话令牌（`session_token`）是按会话签发的，不能拿来当用户级钥匙。v3 新增**所有者令牌**：

- `POST /api/v3/memory/enable` 首次开启记忆时，服务端生成 32 字节随机 `owner_token`，只存 `sha256` 到 `v3_owner.owner_key_hash`，明文**仅此一次**返回给客户端；
- 客户端存 `localStorage.owner_token`，此后所有 `/api/v3/*` 带 `X-Owner-Token`；校验失败统一 **404**（不区分「不存在」与「无权限」，沿用 v2 的 IDOR 口径）；
- `anon_id` 只用于 v2 会话归属与限流，**不作为事实库鉴权依据**；
- **找回机制（P0 最小版）**：开启时同时生成一次性 `恢复码`（20 字符 base32，只存哈希），用户被要求抄下或下载备份文件；换设备/清缓存后用恢复码换新 `owner_token`（旧令牌可选吊销）。真正的账号体系（邮箱 magic link）不在 v3 范围。
- 丢失恢复码 = 事实库不可达。此时数据仍在服务端，按 §9 的保留期处理，**不提供人工找回**（服务端无法验证「你是你」）。这条必须在 UI 上写死，不能含糊。

## 5. 数据模型（`supabase/migrations/2026MMDD_v3_memory.sql`）

```sql
-- 所有者：跨会话事实与简历的归属根，只认 token 哈希
create table public.v3_owner (
  id uuid primary key default gen_random_uuid(),
  owner_key_hash text not null unique check (length(owner_key_hash) = 64),
  recovery_hash text check (recovery_hash is null or length(recovery_hash) = 64),
  anon_id text,                            -- 首建时的匿名 ID，仅作来源线索，不鉴权
  memory_enabled boolean not null default false,
  consent_at timestamptz,                  -- 明示同意时间，未同意不得写入事实
  created_at timestamptz not null default now(),
  last_seen_at timestamptz not null default now(),
  deleted_at timestamptz
);

-- 事实：一条 = 一个原子值；value 必为来源原话的逐字子串（服务端校验）
create table public.v3_facts (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid not null references public.v3_owner(id) on delete cascade,
  kind text not null check (kind in
    ('identity','goal','education','experience','skill','award','metric','constraint')),
  slot_path text not null check (length(slot_path) between 1 and 120),
  value jsonb not null,                    -- 字符串/数字/短对象；单条 ≤512 字符
  value_hash text not null check (length(value_hash) = 64),   -- sha256(kind+slot+规范化 value)
  status text not null default 'proposed'
    check (status in ('proposed','confirmed','rejected','superseded')),
  confidence numeric(3,2) not null default 0 check (confidence between 0 and 1),
  source_session_id uuid references public.chat_sessions(id) on delete set null,
  source_message_id bigint,
  evidence jsonb not null default '[]' check (jsonb_typeof(evidence) = 'array'),
  superseded_by uuid references public.v3_facts(id),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  deleted_at timestamptz
);
create unique index v3_facts_dedup_idx
  on public.v3_facts(owner_id, value_hash) where deleted_at is null;
create index v3_facts_slot_idx
  on public.v3_facts(owner_id, kind, slot_path) where deleted_at is null;

-- 增量抽取水位：同一会话同一段消息只抽一次
create table public.v3_extraction_state (
  owner_id uuid not null references public.v3_owner(id) on delete cascade,
  session_id uuid not null references public.chat_sessions(id) on delete cascade,
  last_message_id bigint not null default 0,
  attempts integer not null default 0,
  last_error_code text,
  extracted_at timestamptz,
  primary key (owner_id, session_id)
);

-- 岗位简历：字段 + 证据 + 事实快照；快照让「事实变了」可被发现
create table public.v3_resume_documents (
  id uuid primary key default gen_random_uuid(),
  owner_id uuid not null references public.v3_owner(id) on delete cascade,
  title text not null check (length(title) between 1 and 80),
  template_version text not null,
  target_role text,
  jd_digest text,                          -- JD 的关键词摘要，不存全文
  fields jsonb not null default '{}',
  evidence_map jsonb not null default '{}',
  gaps jsonb not null default '[]',
  fact_snapshot jsonb not null default '[]',   -- [{fact_id, value_hash}]
  status text not null default 'draft' check (status in ('draft','ready','archived')),
  version bigint not null default 0,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  deleted_at timestamptz
);
create index v3_resume_owner_idx
  on public.v3_resume_documents(owner_id, updated_at desc) where deleted_at is null;

-- 复用 v2 已有触发器函数（20261117_v2_memory.sql）
create trigger v3_facts_touch before update on public.v3_facts
for each row execute function public.v2_touch_updated_at();
create trigger v3_resume_touch before update on public.v3_resume_documents
for each row execute function public.v2_touch_updated_at();
```

新函数同样需要 `revoke … from public, anon, authenticated` 且只 `grant execute … to service_role`（与 `v2_*` 函数同口径）。

**访问控制**：四张表全部 `enable row level security`，不建任何 anon/authenticated policy，只走 service key（与 `v2_quota_bucket` 同口径）。**不引入 pgvector**：单用户事实量级是几十到几百条，按 `kind/slot_path` 全取 + 关键词排序足够；等真实样本证明不够再加，别提前上重依赖。

**清理口径**：v2 的 90 天会话清理**不动 v3 表**；但 `source_session_id` 是 `on delete set null`，事实本身保留，UI 标「来源会话已过期删除」。所有者级保留期见 §9。

## 6. 事实抽取流水线（核心）

```
触发点：会话 stage 进入 wrapping/done 后（异步），或每 4 轮一次；
        也可由 POST /api/v3/facts/extract 手动触发（调试/收尾）
输入：v3_extraction_state.last_message_id 之后的**增量**用户消息
      + 已确认事实的「slot 摘要」（只给槽位名，不给值，防止模型复述旧值）
模型：qwen-turbo json_mode（与 v2 extractor 同档，不占 plus 配额）
输出：{facts:[{kind, slot_path, value, msg_id, quote, confidence}],
        conflicts:[{slot_path, existing_hint, new_value}], denied:[]}
```

服务端校验（**全部硬校验，任一不过整条丢弃**，与 v2 autofill 同一红线）：

1. `msg_id` 必须在该会话真实存在且 `role='user'`；`quote` 必须是该消息的**连续逐字子串**；
2. `value` 必须出现在 `quote` 内（extractive，不做改写/拼接/概括）；
3. `kind/slot_path` 必须在白名单内（复用模板契约的 section/entry 字段路径，见 §7）；
4. 单条 `value` ≤512 字符，单轮最多 20 条，`confidence` 为 0–1 的数字；
5. 敏感信息 deny 正则（身份证号、银行卡、家庭住址、政治面貌、健康信息）命中即整条丢弃，不落库；
6. 与已有 `value_hash` 相同 → 不新建，只把新来源追加进 `evidence`（≤8 条，防膨胀）；
7. 同 `slot_path` 已有 `confirmed` 且值不同 → 不覆盖，写 `conflicts`，生成一条待确认事实（`proposed`）。

**状态机**：`proposed → confirmed | rejected`；`confirmed` 被新值取代时旧行 `superseded`（保留可追溯）。**自动确认只限低风险类别**：`skill` / `education` / `identity` 且 quote 完整（覆盖 value 全部字符）时自动 `confirmed`；`experience` / `metric` / `award` / `goal` 一律 `proposed`，等用户点一次「确认」或「全部确认」。

**幂等与失败**：抽取前先按 `(owner_id, session_id)` 推进水位；失败只记 `attempts/last_error_code`，不影响聊天；连续 3 次失败的会话进 `blocked` 状态，等下一次会话结束再重试。**历史回填**（v2 老会话）是单独的一次性任务（#13），有独立预算与进度条，不做成后台静默全量跑。

**抽取器为什么不用 plus**：这是「照抄原话 + 分类」，不是创作；turbo 足够，且失败可重试，成本可控。

## 7. 岗位简历生成

**输入**：`{title, target_role?, jd_text?, template_version}`。
**流程**：

1. 取该 owner 全部 `status in ('confirmed','proposed')` 且未删除的事实（proposed 也可参与生成，但在 evidence 里标注「待确认」，导出前提示）；
2. **相关性排序**：`target_role`/JD 关键词与 `slot_path + value` 的关键词命中数为主序，`confirmed` 优先，`confidence` 次序；不做向量检索；
3. **组装成 v2 profile 形状**（`identity/goal/experiences/skills/...`），复用 v2 已验证的「profile → 模板字段」逻辑，把 `autofill` 里那段 prompt 与校验抽成 `build_fields_from_facts()`，输出 `{fields, evidence_map, gaps}`；
4. 落库为 `draft`，`fact_snapshot` 记录本次参与的 `{fact_id, value_hash}`；
5. 用户编辑：任何被手工改过的字段标 `manual_override`（存 `fields` 内旁路 `_meta.manual_override: [path...]`），**重新生成时不覆盖手工字段**，除非用户勾选「全部重生成」；
6. 事实变更传播：`PATCH/DELETE /facts` 后，对比 `fact_snapshot`，受影响字段进 `stale_sources`，UI 黄条「来源已更新/已删除，建议重新生成」，**不静默改稿**；
7. 版本：每次保存 `version+1`，保留最近 10 版可取回。

**红线复用**：数字/公司/技术/奖项一律走 v2 已有的 `_guard_fabricated_numbers` 与 claim-evidence 校验；占位符 `【待补充:字段名】` 不算完成内容，导出前必须列清单二次确认。**v3 不新开一套守卫**，只是把事实库当作证据源接进同一条守卫链。

**优化（STAR 改写）**：沿用 v2 的 `optimize/plan` + 逐段 `optimize/section`，只是把请求从「当前会话 autofill 结果」换成「某份 document 的 fields」。P3 再做，P0–P2 只保证生成与编辑可用。

## 8. 接口契约（`/api/v3/*`）

| 方法 | 路径 | 请求 | 响应要点 |
|---|---|---|---|
| POST | `/api/v3/memory/enable` | `{recovery: bool}` | `{owner_token, recovery_code?, owner_id}`，`owner_token` 仅此一次明文返回 |
| GET | `/api/v3/memory` | — | `{enabled, consent_at, fact_count, by_kind, by_status, last_extracted_at}` |
| POST | `/api/v3/memory/disable` | — | 停止抽取；数据保留（清空走 DELETE） |
| DELETE | `/api/v3/memory` | `{confirm: "DELETE_ALL"}` | 硬删 owner + facts + documents，返回删除计数 |
| GET | `/api/v3/memory/export` | — | 全量 JSON（事实 + 证据 quote + 简历），`Content-Disposition: attachment` |
| DELETE | `/api/v3/memory/sessions/{session_id}` | — | 「忘掉这个会话」：`{facts_detached, documents_scrubbed}`；剥除来源指针、该会话证据 quote 与全部文档 `evidence_map` 中的该会话条目 |
| POST | `/api/v3/memory/recover` | `{recovery_code, revoke_old?: bool}` | 恢复码换发新 `owner_token`（旧令牌可选吊销），明文仅此一次返回（P3，#16） |
| POST | `/api/v3/memory/backfill` | `{session_ids?: ≤30}` | 不传则按 `owner.anon_id` 名下 v2 会话全量回填；逐会话独立水位，`{results:[{session_id, added, merged, conflicts, skipped} \| {error}]}` |
| GET | `/api/v3/facts` | `?kind=&status=&cursor=&limit=` | `{facts:[{id,kind,slot_path,value,status,evidence:[{session_id,msg_id,quote}],created_at}],next_cursor}` |
| PATCH | `/api/v3/facts/{id}` | `{status?: "confirmed"/"rejected", value?}` | 改值 = 新建一条 + 旧条 superseded；返回新事实 id |
| DELETE | `/api/v3/facts/{id}` | — | 软删 + 受影响简历标 `stale_sources` |
| POST | `/api/v3/facts/extract` | `{session_id}` | 幂等增量抽取，`{added, merged, conflicts, skipped}` |
| GET | `/api/v3/resumes` | — | 列表：`{id,title,target_role,status,completeness,updated_at}`（不含全文） |
| POST | `/api/v3/resumes` | `{title, target_role?, jd_text?, template_version}` | `{document}`，含 fields/evidence_map/gaps |
| GET | `/api/v3/resumes/{id}` | — | 文档详情 + `stale_sources` |
| PATCH | `/api/v3/resumes/{id}` | `{title?, fields?, status?}` + `If-Match: version` | 版本冲突 409；成功 `version+1` |
| DELETE | `/api/v3/resumes/{id}` | — | 软删 |
| POST | `/api/v3/resumes/{id}/regenerate` | `{target_role?, jd_text?, keep_manual: true}` | 新版本草稿，手工字段默认保留 |
| POST | `/api/v3/resumes/{id}/duplicate` | — | 整稿深拷贝为新草稿（字段/证据/快照全复制，version 归零），返回 `{document}`（P3） |
| GET | `/api/v3/resumes/{id}/versions` | — | `{versions:[{version, created_at, reason}]}`，写入前快照、最新保留 10 版 |
| POST | `/api/v3/resumes/{id}/versions/{v}/restore` | — | 把快照还原为**新版本**（还原前先快照当前版 → 可再撤销），返回 `{document}` |
| POST | `/api/v3/resumes/batch` | `{items: ≤5, template_version?}` | 批量生成，`{results:[{document?, error?}]}`，单项失败不阻断整体 |

**通用约定**：所有响应带 `protocol: 3`；错误沿用 v2 形状 `{code, message, retryable}`；`X-Owner-Token` 缺失/错误 → 404；限流复用 `security.enforce_ip` + `model_budget` 日预算，另加 owner 级日限额（抽取 30 次/天、生成 20 次/天）；一切 LLM 调用前先走 `model_budget.reserve()`，与 v2 同一闸门。配额/预算耗尽的终态：单资源端点 → **429**（`code: "rate_limited"`）；批量端点（`/memory/backfill`、`/resumes/batch`）→ 200 + 对应项 `{"error": "daily_quota"}`，不中断其余项。`POST /resumes/{id}` 版本冲突 → 409。

## 9. 隐私、删除与保留期

- **默认关闭**：`memory_enabled` 为 false 时，v2 行为完全不变，不写任何事实；开启必须点同意（前端弹窗 + `consent_at` 落库）。
- **三级删除**：① 单条事实删除（软删，证据随之不可见）；② 「忘掉这个会话」：该会话来源的事实标 `source_session_id = null`，UI 显示「来源会话已删除」，用户可逐条决定保留或删除；③ 清空全部（硬删 owner 级联）。
- **导出**：任何时候可导出 JSON 备份（事实 + 证据 + 全部简历），格式带 `schema_version`，可读可带走。
- **保留期**：owner 连续 365 天无活动 → 提前 30 天在站内提示，之后硬删；删除任务先 dry-run 报表再执行（复用 v2 `v2_prune_quota` 的做法）。
- **日志**：只记 `owner_id/session_id/计数/耗时/错误码`，**不记 quote 与字段正文**；现有 `test_privacy_hygiene.py` 的 no-print/no-traceback 断言必须继续通过（新增代码不得引入日志出口）。
- **不抽取**：身份证号、银行卡、详细住址、政治面貌、健康/宗教等敏感项，deny 正则命中即丢弃；`kind` 白名单本身也限制了范围。
- **简历默认私有**：v3 不做公开分享链接；若未来要做，必须独立签名 token + 过期 + 可撤销。

## 14. 风险与不做

**风险**

| 风险 | 影响 | 对策 |
|---|---|---|
| 用户丢恢复码 | 长期事实不可达，投诉 | 开启时强制抄写/下载；导出按钮常驻；文案写明无人工找回 |
| 抽取误差累积 | 错事实被多份简历引用 | 只做 extractive + 硬校验；P1 起默认 `proposed` 需确认；G2 精确率门槛 |
| 事实过时（换目标、涨 GPA） | 简历写到旧信息 | `superseded` 状态机 + 冲突待确认 + stale 提示 |
| 成本被单用户刷爆 | 全局预算被占 | owner 级日限额 + 全局 `model_budget` 双闸门 |
| 隐私合规 | 作品/上线风险 | 默认关闭 + 同意 + 三级删除 + 导出 + 敏感项 denylist |
| 单人工期 | 做不完 | P0–P2 为交付底线，P3 全部可延期 |

**明确不做**

- 不做公开简历分享链接、不做二维码/短链（隐私面太大，需要单独设计）；
- 不做自动投递、JD 爬取/岗位库、薪资数据；
- 不做邮箱/手机号账号体系（v3 只到恢复码；账号是 v4 的题目）；
- 不引 pgvector / 向量数据库 / 事件总线 / 新前端组件库；
- 不做多人共享简历、团队协作；
- 不改 v2 的 SSE 协议、profile schema、模板契约形状（只在其上加 `evidence.fact_id` 之类的**新增可选键**，且必须同步 fixture + 双方 ack）。
