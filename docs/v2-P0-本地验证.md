  由 `V2_SHARED_QUOTA=1` 启用；开关默认 `0`，且必须先应用配额迁移，否则 anon 轮次配额会 fail-closed 返回 503。

## 本地测试

Windows 项目根目录运行（离线，全部走 `httpx.MockTransport`）：

```bash
NO_PROXY="localhost,127.0.0.1" PYTHONPATH="backend:." python -B -m unittest discover -s tests -p 'test_*.py'
```

`NO_PROXY` 必须覆写：本机环境里的 `NO_PROXY` 含 `[::1]`，httpx 0.28 解析会抛 `InvalidURL`，与代码无关。
只运行 `test_*.py` 离线测试；不要误运行默认指向线上服务的 `route_cases.py` 或 `rag_e2e.py`。
存储测试使用 `httpx.MockTransport` 和测试配置，不依赖真实数据库。

## 数据库验收清单（已执行）

执行记录与复跑命令见 `docs/v2-迁移验收记录.md`：隔离 PostgreSQL 16.4 实例、空库、脚本化断言 **96 通过 / 0 失败**（`tests/v2_db_acceptance.sh`）。
下面是清单本身与对应段落；线上项目仍需按同口径复跑一次（pgvector 与真实 PostgREST 角色只能在真项目验证）。

在新建的隔离 Supabase 测试项目上，使用项目数据库迁移管理员执行正向迁移。普通 PostgreSQL 需先由管理员准备 Supabase 的 `anon`、`authenticated`、`service_role` 等角色；不要在现有生产库模拟这些角色。

1. 三表、索引和约束创建成功；错误 stage、role、status、coverage、空匿名 ID、非哈希令牌被拒绝。
2. 创建会话时原子生成 version=0 的画像；更新会话和画像触发 updated_at。
3. 同会话同 client_msg_id 的用户消息只能插入一次；assistant 消息不受该用户专用唯一索引限制。
4. 首条用户消息生成前 20 字标题；后续消息不覆盖；消息插入原子更新 last_message_at。
5. anon/authenticated 无法读写三表和调用清理 RPC；service_role 可通过 REST 正常操作，不能把 service key 发给浏览器。
6. 造一条超过 90 天的测试会话和一条活跃会话。dry-run 仅计数、不删除；显式执行后只删除过期会话，并级联删除对应消息/画像。
7. 并发画像写入同一 expected_version，只允许一个成功。
8. 确认回滚目标确为隔离测试项目并备份后，手动执行 rollback 子目录脚本；验证 v2 对象移除、知识库对象不受影响。

## 清理调度（函数已验收 · 线上定时器待注册）

两条已验证的落地路径，任选其一即可，两者都不要在请求入口里顺手做物理清理：

1. **数据库侧 pg_cron（推荐）**：应用 `supabase/migrations/20261118_v2_cleanup_schedule.sql`，它先干跑核对命中行数，再注册两个作业
   （`zhimai_v2_session_cleanup` 每日 90 天删除、`zhimai_v2_quota_prune` 回收陈旧窗口与死租约），文件尾部给出 `cron.job` / `cron.job_run_details` 验证查询；回滚为 `rollback/` 同名文件。
2. **管理接口**：登录后调用 `POST /api/admin/cleanup`，请求体 `{"days":90,"dry_run":true}` 先看命中行数，再显式 `{"days":90,"dry_run":false}` 执行；
   响应只有计数，没有正文与令牌，参数为 strict（字符串 `"false"` 不会被悄悄当成 `false`），存储故障返回脱敏 503。
   由运维自建的 FC/外部定时器也可走同一条：`backend.memory.cleanup_expired(90, False)` + `backend.memory.prune_quota(False)`。

仅提供清理函数不等于已经安装定时任务：线上必须看到 `cron.job` 有记录且 `job_run_details` 出现 `status='success'`（或等价的定时器触发日志），才算配置完成。
隔离库已用「作业实际执行的那条语句」复跑两次验证过幂等与边界（见验收记录 9b 段），但 pg_cron 本身在便携版 PostgreSQL 里不可用，注册动作仍待线上执行。
