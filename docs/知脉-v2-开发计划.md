# 知脉 · v2.0 开发计划 —— 简历成长教练

> 状态：已按 2026-11-16 两轮审查修订，含两人协作与 Issues 工作流 ｜ 基线：v1.0（main，线上运行中）
> 开工前先打 `v1.0.0-submission` tag；v1 问答入口与接口在 v2 验证通过前不删除。
> 范式参照：Stanford STORM（提问→策展→成文）、MockMate/Friday（访谈多智能体）、Letta（三层记忆）、Dify（agent_thought 事件协议）、Vercel AI SDK（UIMessage 持久化）

## 0. 审查结论与开工门槛

v2 方向成立，但不能直接按原 P0–P4 开工。以下 6 项未落定前，不进入访谈/简历业务代码（P0 安全与存储本身就是第一批任务）：

1. **会话授权与隐私**：服务端签发会话令牌，所有会话读写/删除校验归属；限流、配额、删除与 90 天过期任务随 P0 上线，隐私文案同批更新。
2. **数据模型定稿**：覆盖率单一事实源、`updated_at` 触发器、消息状态/幂等键、约束与清理任务写入迁移。
3. **模板契约单一来源**：Python 加载带版本的契约 JSON，Vue 只通过 `/api/v2/resume/template` 读取同一份，禁止双份硬编码。
4. **接口版本化与回滚**：新增 `/api/v2/*`，旧 `/api/chat/stream` 保留；Sites 与 FC 可分开发布，v1 可随时恢复。
5. **编排 spike**：验证 qwen-turbo JSON 编排、`decision-model-preview` 仅做意图、`reasoning_content` 支持与延迟预算；失败时有规则兜底。
6. **优化超时实测**：FC 120 秒限制下，analyze + 单 section 改写必须实测 p95；客户端逐段编排已是默认，仍不达标则缩范围或延期 P3。

### 交付路径

- **赛前切片（若 11/30 前必须上线）**：只做 P0 安全地基 + 最小访谈 + 单模板 autofill/打印；保留 v1 独立问答；P3 黑箱优化与多模板延期。以 11/16 起算不足两周，切片也需并行并继续砍范围。
- **赛后完整 v2**：按 P0→P1→P2→P3→P4 推进，1 人粗估 4–5 周；每个 Gate 不通过不进入下一阶段。
- **默认建议**：v1 冻结提交，v2 赛后迭代，避免在截止前替换线上核心链路。


## 0.1 版本定位与原则

v1 = 被动问答机（检索→回答→结束）。v2 = **主动引导的求职教练**：AI 先开口 → 多轮反问刻画用户画像、深挖经历 → 一键把素材填进简历模板 → 黑箱自动优化成稿。知识库在整个过程中作为"工具"被按需调用，思考过程全程可见。

**北极星指标**：用户从打开到拿到一份可导出优化简历，全程不需要会写 prompt；每一步都能看到 AI"做了什么、为什么做"。

**选型总则：开发速度优先**——不引新框架、不引 UI 组件库、不引 LaTeX/Typst 排版管线、无重型依赖；全部复用现有栈（FastAPI + Supabase REST + Vue3 纯 CSS + 浏览器打印）。路由沿用现有 hash/tab 模式（同 `#admin`），不引 vue-router。

## 1. 用户旅程（三段式）

```
① 访谈挖掘                ② 建简历                     ③ 黑箱优化
AI招呼→邀请开启旅程        [新建简历]→[一键填写]          导出后→[一键优化]
逐轮反问/顺带答知识        模板字段自动填充(带来源标注)    analyze→STAR→守卫 全在黑箱
画像面板实时积累           人工修改→实时预览→导出         进度可见+改动日志+占位待补
覆盖率达标→收尾总结+引导卡 ────────────┐        产出优化版简历(可再导出)
   │                                  │               ▲
   └─ 对话上下文(服务端会话) ────────────┘  简历字段 ─────┘
```

> 修订：保留“直接问知识”入口。AI 招呼同时给出「开始访谈」与「直接提问」两个选择；访谈中也可随时问知识，答完再自然带回访谈线。AI 先开口不等于强制访谈。

## 3. 数据模型（supabase/migrations 新增）

```sql
create table chat_sessions (
  id uuid primary key default gen_random_uuid(),
  anon_id text not null,                    -- 前端 crypto.randomUUID()，仅作匿名分区
  session_token_hash text not null,         -- 服务端签发令牌的哈希，明文只回给客户端
  title text not null default '新会话',
  stage text not null default 'greeting'
    check (stage in ('greeting','probing','wrapping','done')),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  last_message_at timestamptz not null default now()
);
create index chat_sessions_anon_idx on chat_sessions(anon_id, updated_at desc);

create table chat_messages (
  id bigint generated always as identity primary key,
  session_id uuid not null references chat_sessions(id) on delete cascade,
  client_msg_id text,                       -- 客户端幂等键，防重复发送
  role text not null check (role in ('user','assistant','system')),
  content text not null,
  status text not null default 'done'
    check (status in ('streaming','done','error')),
  steps jsonb not null default '[]',        -- UIMessage 形状：思考过程可回放
  sources jsonb not null default '[]',      -- 入库前必须走 to_mirror_url
  meta jsonb not null default '{}',
  created_at timestamptz not null default now()
);
create index chat_messages_session_idx on chat_messages(session_id, id);
create unique index chat_messages_client_msg_idx
  on chat_messages(session_id, client_msg_id)
  where client_msg_id is not null and role = 'user';

create table user_profiles (
  session_id uuid primary key references chat_sessions(id) on delete cascade,
  profile jsonb not null default '{}',      -- Letta human block：始终注入 system
  coverage numeric(4,3) not null default 0  -- 覆盖率唯一事实源，0–1
    check (coverage between 0 and 1),
  coverage_detail jsonb not null default '{}', -- 各 section/slot 明细，供画像面板
  version bigint not null default 0,        -- profile merge 乐观锁
  updated_at timestamptz not null default now()
);

create or replace function touch_updated_at() returns trigger as $$
begin new.updated_at = now(); return new; end;
$$ language plpgsql;

create trigger chat_sessions_touch before update on chat_sessions
for each row execute function touch_updated_at();
create trigger user_profiles_touch before update on user_profiles
for each row execute function touch_updated_at();
```

**约束与清理**：会话令牌只存哈希；所有会话读写/删除校验 `anon_id + session_token` 归属；覆盖率以 `user_profiles.coverage` 为唯一事实源，`chat_sessions` 不再双写浮点值；`last_message_at` 在消息落库时同步更新；90 天无活动会话由 pg_cron 或 FC 定时任务每日物理删除。

**profile JSONB 结构**（STORM InformationTable 式，带覆盖度）：

```json
{"identity":{"grade":"","major":"","school":""},
 "goal":{"direction":"","target_role":"","timeline":""},
 "experiences":[{"type":"internship|project|campus|competition","title":"",
   "role":"","actions":[],"results":[],"metrics":[],"star_score":0}],
 "skills":[], "constraints":{"city":"","availability":""}, "needs":[]}
```

**简历不落库（已定）**：简历 fields 存前端 **localStorage**（JSON 仅 KB 级，同步 API 比 IndexedDB 快且无依赖），autofill/optimize 均为一次性请求过境，服务端不落库、日志不记字段内容。代价：换设备简历不跟随，文案需说明。⚠ 对话内容将落库（新数据收集），隐私文案必须更新 + 提供删会话按钮。

## 4. SSE 事件协议 v2（照 AI SDK / Dify 形状）

```
event: session     {protocol:2, session_id, session_token?, stage, is_new}
event: step_start  {id, seq, kind, title}   kind: recall|plan|retrieve|grade|reflect|profile|guide
event: step_end    {id, seq, detail, status} detail 仅放整理后的 query/hits/score/slot_changes
event: reasoning_summary  "整理后的思考摘要"  不传原始 chain-of-thought / 系统提示
event: token       "增量回复"
event: sources     [{title,url,seq,score}]   url 必须是镜像地址
event: profile     {coverage, gaps, updates}
event: card        {type:"goto_resume"|"suggest_reply", payload}
event: done        {session_id, message_id, stage, coverage}
event: error       {code, message, retryable}
```

**流式持久化规则**：`reasoning_summary` 由服务端根据 step 结果生成，不转发模型原始 CoT 或系统提示。用户消息先落库；assistant 消息以 `status=streaming` 落库，正常结束改 `done`，异常改 `error`；`done/error` 必须终结事件。客户端断线后通过 `GET /api/v2/sessions/{id}` 恢复，不依赖重放同一流。旧 `/api/chat/stream` 保持 v1 事件形状，供回滚使用。

## 5. 接口契约

| 接口 | 说明 |
|---|---|
| `POST /api/v2/chat/stream` | 头 `X-Anon-Id`；已有会话再加 `X-Session-Token`。`{session_id?, client_msg_id, message?}`；无 session 时建会话，`message` 为空先流式发招呼，否则直接进入首轮 |
| `GET /api/v2/sessions` | 头 `X-Anon-Id`；只返回该匿名 ID 的会话元数据（id/title/stage/时间），不含正文 |
| `GET /api/v2/sessions/{id}` | 头 `X-Anon-Id + X-Session-Token`；校验归属，失败返回 404 |
| `DELETE /api/v2/sessions/{id}` | 同上；级联删除消息与画像，UI 二次确认 |
| `POST /api/v2/messages` | P0 过渡专用：`{session_id, client_msg_id, user, assistant}` 回写一轮旧链路问答；v2 链路不调用（服务端在流内落库），P1 后下线 |
| `GET /api/v2/resume/template` | 返回带 `template_version` 的契约 JSON，前后端共用 |
| `POST /api/v2/resume/autofill` | 头 `X-Anon-Id + X-Session-Token`；`{session_id, template_version}` → `{fields, evidence_map, gaps}` |
| `POST /api/v2/resume/optimize/plan` | 头 `X-Anon-Id`；`{template_version, fields}` → 待优化 section 列表；不落简历 |
| `POST /api/v2/resume/optimize/section` | 头 `X-Anon-Id`；`{template_version, section, fields}` → 单段结果；客户端逐段调用，控制在 FC 超时内 |
| 保留 | `/api/chat/stream`（v1 回滚）、`/api/route`（内部意图）、`/api/resume/rewrite`（内部复用） |

**契约与限流**：所有 LLM JSON 输出先过 Pydantic/JSON Schema，失败修复重试 1 次，再失败返回安全兜底；匿名 ID、IP、会话分别限流（轮数/条数/字符数），禁止无限会话与无限 token。

## 6. 访谈引擎 coach.py（核心新模块）

**多角色分离**（MockMate/Friday 共识：评估与提问必须分上下文）：

```
L1 规则（招呼/直接提问/跳过/收尾）→ 命中即走，不调编排模型
orchestrator(qwen-turbo json；spike 未通过前不把 decision-model 当编排器)
  → {act: ask|answer|wrap_up, need_kb, focus_slot, reason, deep}
      ↓ step.plan
  retrieve 工具（仅 need_kb）→ kb.search → CRAG打分→低分重写query重试1次
      ↓ step.retrieve/step_end(命中数/最高分) + sources
  interviewer(qwen-plus；deep 轮可选 thinking)
      ↓ token 流（reasoning_summary 由服务端按步骤生成）
  extractor(qwen-turbo json_mode)：本轮→{new_facts, slot_updates, quotes}
      ↓ 服务端校验 quote 是用户原话子串 → profile merge + coverage 更新
  coverage 达标或 max_turns 到顶 → wrap_up：总结卡+素材清单+card(goto_resume)
  持久化：2条消息(含steps)+profile+stage
```

**编排选型（必须先 spike）**：默认 qwen-turbo JSON 做多字段编排，`decision-model-preview` 只负责意图；spike 要验证 `enable_thinking/reasoning_content` 是否可得、首 token 与整轮延迟。失败兜底：按模板 gap 选择下一个 slot，仍可回答知识问题，不能把编排失败变成整轮报错。

**覆盖度与收尾（必须可计算）**：
- `coverage = 有证据的必填 slot 数 / 适配后的必填 slot 总数`；覆盖率唯一事实源是 `user_profiles.coverage`。
- 必填 slot 按年级与已有经历自适应：无实习不强制实习；项目要求为“2 段项目或等价经历”，不把大一用户卡死。
- `star_score` 按情境/任务、行动、结果、量化四项各 1 分归一化；收尾建议 `coverage >= 0.8` 且至少 1 段经历 `star_score >= 0.6`。
- 最大 12 轮；到顶不硬追问，输出 gaps 和可填部分，允许用户先 autofill。

**画像合并红线**：extractor 只提出 `slot_updates`，服务端校验 quote 必须能在对应用户消息中找到；用户明确确认的字段不得被模型覆盖；冲突时保留双方并生成一次确认问题。

**延迟预算**：首个 step 事件 <300ms；首个 token p50 <3s、p95 <8s；整轮 p95 <12s；超过预算自动降级为“先回答/后补画像”，不得无限等待。

**Interviewer prompt 资产**（新建 `backend/prompts/`）：
- `coach_system.md`：人设=求职教练；规则=每轮只问一个点、先回应再追问、可用知识库做钩子、禁止报分/报进度给用户听
- `interview_plan`：由模板契约 slot 集反推（§8），维度顺序 身份→目标→经历逐个深挖(STAR:做了什么/怎么做/结果数据)→技能→约束
- `extractor.md`、`autofill.md`、`wrapup.md` 各一份，全部走 json_mode

**上下文组装**（Letta 式：画像代替全历史）：`system = persona + profile block + 当前gaps + KB ctx` + 最近 8 轮消息。profile 常驻 → 老消息可裁，省 token。

**防"查户口"**：orchestrator 每轮先判"用户在问知识还是在接受访谈"——问知识就走 retrieve+answer 自然回答，答完顺势带回访谈线。闲聊不强行拉回。

## 7. 记忆设计（Letta 三层映射）

| 层 | 实现 | 进出方式 |
|---|---|---|
| core(human block) | `user_profiles.profile` 常驻 system | extractor 每轮 merge |
| recall | `chat_messages` 全量 | 服务端取最近8轮+按需 |
| archival | 现有 `chunks` 知识库 | retrieve 工具按需 |
| persona | `prompts/coach_system.md` | 静态 |

历史回放存 UIMessage（steps/sources 一并入库），思考过程可回看。

**归属与清理**：recall 查询必须带 `session_id` 且先过令牌归属校验；删除会话级联删除 messages/profile；90 天无活动会话物理删除；应用日志只记 id/长度/耗时，不记消息正文与令牌；回放只展示整理后的 `steps`，不存原始 chain-of-thought。

## 8. 优秀模板简历：全链路锚点（核心新增）

**一份模板契约，五处消费**——契约存为 `backend/resume_template.json`（带 `template_version`），由 `backend/resume_template.py` 加载并做 JSON Schema 校验，`GET /api/v2/resume/template` 是唯一出口；Python 与 Vue 都不得再硬编码字段：

```
模板契约(TEMPLATE)
 ├─ 访谈提纲：每个字段/经历条目=待填slot；bullet_rubric=追问深度标准
 ├─ coverage判定：各section可填充质量分→orchestrator"还缺什么"=模板gap分析
 ├─ autofill目标schema：profile→模板字段映射+evidence_map字段路径
 ├─ 前端预览渲染+打印导出（Vue组件按契约渲染，加模板只需加契约）
 └─ optimize评分细则：改写质量对标rubric，而非自由发挥
```

**校招简历字段共识**（牛客校招帖×ATS指南交叉验证，入库契约）：

```jsonc
{
  "template_version": "1.0.0",
  "page_rule": "单栏一页；求职意向紧跟姓名；经历按含金量不按时间排",
  "sections": [
    {"key":"basics","title":"基本信息",
     "required":["name","phone","email","target_role"],
     "optional":["github","blog","city"],
     "rules":"不写籍贯/政治面貌(国企除外)"},
    {"key":"education","title":"教育背景","min":1,"max":1,
     "fields":["school","major","degree","period"],
     "optional_fields":["gpa_or_rank","courses"],
     "quality":"GPA≥3.5或前20%才写；本科可附主修课程"},
    {"key":"internships","title":"实习经历","min":0,"priority":1,
     "fields":["company","role","period","bullets[]"],
     "bullet_rubric":"STAR：情境→行动→量化结果；动词开头；每条≥1硬数据；体现个人贡献"},
    {"key":"projects","title":"项目经历","min":2,"max":3,"priority":2,
     "fields":["name","role","period","tech[]","bullets[]"],
     "bullet_rubric":"同实习；技术栈标签化；优先开源/竞赛/自研，避免课程大作业"},
    {"key":"skills","title":"专业技能",
     "format":"分组标签：语言/框架/工具",
     "rules":"'熟悉/了解'分档，不写'精通'"},
    {"key":"awards","title":"荣誉奖项","optional":true},
    {"key":"summary","title":"自我评价","optional":true,"rules":"30字内对齐岗位"}
  ]
}
```

**契约版本与自适应**：`template_version` 用 semver；autofill/optimize 请求必须带版本，服务端版本不匹配直接返回 `409` 让前端重取，禁止静默按旧字段猜。`min/required` 只是默认值，按年级与已有经历适配：无实习不强制实习，项目可用竞赛/开源/科研等价替换，不把低年级用户卡在固定数量上。

**证据与占位**：autofill 只填有证据的字段；`evidence_map` 的 quote 必须能在该会话消息中找到，否则丢弃该证据并降级为 gap。缺失字段统一进 `gaps`，前端黄标 `【待补充:字段名】`，不得用模型常识补全。

**许可与实现**：NewFuture/CV 仅作 MIT 许可下的版式参考；落地 CSS 自行重写为普通 CSS，不引入 Sass 构建链。所有借鉴来源与许可证登记到 `docs/开源许可.md`。

**访谈 slot 由此推导**：每个 internship/project 条目 = `{标题, 角色, 时间, 情境/任务, 行动/技术, 结果数据}` 一组 slot；orchestrator 每轮挑"模板里最缺质量的 slot"追问——这就是防发散的机制。

**模板选型（最快路径）**：默认 1 套单栏中文校招模板 = **契约驱动的通用 section 渲染器**（Vue `v-for` 渲染契约，不为每字段写死 markup）+ 参考 MIT 许可中文简历的版式后用普通 CSS 重写（按 sb2nov/Jake's 单栏版式与 billryan 中文排版微调）。导出沿用浏览器打印。**不做** LaTeX/Typst 服务端排版（FC 依赖太重）、不内嵌 Reactive Resume（编辑器太重）、不引入 Sass 构建；后续多模板=多契约文件+一套 CSS。

autofill 输出 `{fields, evidence_map:{字段路径:[{msg_id,quote}]}, gaps:[待补字段]}`。

## 9. 黑箱优化流水线

**分段编排（FC 超时约束下）**：`plan` 只返回待优化 section 及优先级；前端逐 section 调 `optimize/section`，每次一个请求，单段超时不影响整份简历。

```
fields + template_version → plan(sections按含金量排序)
  → 客户端逐 section：
     analyze(vendor现服务, targeted) → STAR改写(现STAR_PROMPT+bullet_rubric注入)
       → _guard_fabricated_numbers → claim-evidence 校验(公司/角色/技术/奖项须有原文依据)
       → 未通过：该字段内嵌【待补充:XX】+ 生成一个待确认问题
       → optimized_fields + change_log[{field,before,after,reason}]
     → 响应带 steps（诊断/改写/数字校验），前端按段累加展示；单段 error 不阻塞其他段
  → 全部返回后前端合并，保留原稿与优化稿两份
```

**成品边界**：优化稿写独立的 `resume_draft_optimized` key，原稿不被覆盖；用户可逐字段采纳。含占位符的字段标记 `needs_input`，导出时二次确认并列出占位清单。红线：无人可问 → 编造数字被守卫拦后落占位符；占位符不算完成内容，不能静默进入导出。

## 10. 模型分配与成本（每轮访谈）

| 用途 | 模型 | 频率 | 备注 |
|---|---|---|---|
| orchestrator | qwen-turbo json | 每轮 | 多字段编排；L1 命中则跳过 |
| intent 兜底 | decision-model-preview | 条件 | 只输出 intent，不承担编排 |
| interviewer | qwen-plus | 每轮 | deep 轮开 enable_thinking |
| extractor | qwen-turbo json | 每轮 | ~300tok，流后跑；可降为每 3 轮 |
| retrieve | v4 embed + match_chunks | 仅 need_kb | CRAG 重试≤1 |
| autofill | qwen-plus json | 一次 | ~2k tok |
| optimize | 现有链路 | 逐 section | 单段请求，客户端编排 |

每轮 ≈ plus×1 + turbo×1（+条件 intent / 偶发检索），成本可控；step 事件先行发出可掩盖 FC 冷启动。

**配额与熔断**：
- 输入 ≤2000 字符、单轮输出 ≤800 token、单条消息 steps ≤20；超限直接 400，不截断后继续烧 token。
- 限流三层：IP 20 请求/分钟、anon 100 轮/天、session 同时只允许 1 条流；超限返回 429 + `Retry-After`。
- 全局日 token 预算可配置；触顶停止新访谈，保留 v1 问答与已有会话读取。
- 开关 `COACH_ENABLED=0` 一键回退 v1 链路；编排连续失败 3 次自动降级规则式提问。
- 延迟验收沿用 §6 预算：首 step <300ms、首 token p95 <8s、整轮 p95 <12s。

## 11. 前端信息架构

```
App.vue：hash 路由（#chat | #chat/:id | #resume | #admin），不引 vue-router
├ SessionList.vue   侧栏：会话卡+新建+删除（抽屉式，移动端全屏页）
├ InterviewView.vue （ChatView 重构）
│   ├ ThinkingSteps.vue  折叠思考流：icon+title+detail，默认收起显N步
│   ├ ProfilePanel.vue   侧栏：覆盖率环+已收集维度+gaps（可折叠）
│   └ 消息流：来源卡片/引导卡/建议回复 chips 沿用
└ ResumeWizard.vue  ①模板+一键填写 ②左表单右实时预览 ③导出+一键优化+改动对比
storage.js 管 anon_id/草稿；api.js 全量重写为新协议；纯 CSS 不引组件库
```

**路由与刷新**：`#chat/:id` 可直接打开；无 id 为新建。加载时先 `GET /api/v2/sessions/{id}` 校验归属并恢复消息，不依赖重放 SSE；会话不存在/无权限显示提示并回 `#chat`。会话令牌只存本机 `localStorage`，不放 URL、不写日志。

**本地草稿**：`resume_draft_v1` 与 `resume_draft_optimized` 分 key 存储，结构带 `schema_version + template_version`；模板升级时按版本迁移或提示重新填写，不静默丢字段。优化稿不覆盖原稿，支持逐字段采纳。

- **Milestone**：`v2.0`；**labels**：`p0`/`p0.5`/`p1`/`p2`/`p3`/`p4`、`backend`/`frontend`/`shared`/`spike`/`test`/`docs`、`blocked`。

## 13. 评测方案

> 通过门槛全部用确定性脚本或人工抽样，不把“LLM 扮演学生”当验收依据；LLM 回放只用于探索问题。

| 层 | 方法 | 通过线 |
|---|---|---|
| 编排 | 5 条固定回答序列的脚本 persona，断言 act 序列与轮数 | 5/5 收敛，无死循环 |
| 画像 | 脚本事实 vs `user_profiles.profile` diff | 准确≥90%，0 虚构事实 |
| 访谈质量 | 人工按 rubric 抽样：每轮≤1问、有承接、不重复 | 8/10 通过（LLM 评审仅辅助） |
| 检索 | 现有 rag_e2e + CRAG 重试路径 | 10/10 有效，来源均为镜像域名 |
| autofill | golden profile → 字段/evidence_map/gaps 断言 | 证据 quote 100% 可在消息中找到；gaps 无漏报 |
| 黑箱 | 数字守卫 + claim-evidence + 占位标记 + 分段失败隔离 | 0 编造；缺数据 100% 可见占位；单段失败不影响其他段 |
| 安全 | 伪造/过期令牌、越权读写删、级联删除、三层限流 | 负向用例全部通过，越权返回 404 |
| 隐私 | 日志抽检 + 90 天清理 dry-run + 文案检查 | 日志无正文/令牌；清理命中；文案与删除入口在线 |
| 协议 | SSE 事件顺序、`done/error` 终结、断线重连 | 用例 100% 通过，无悬挂流 |
| 延迟 | 生产环境采样首 step/首 token/整轮 | 首 step <300ms；首 token p95 <8s；整轮 p95 <12s |
| 回归 | 现有 `route_cases` 50 条 + `rag_e2e` 原样跑 | 不退化；该套件只覆盖 v1 路由，不代表 v2 访谈质量 |
| 构建 | `pytest` + `npm run build` | 全绿 |

## 14. 风险与熔断

| 风险 | 对策/熔断 |
|---|---|
| 会话越权/IDOR | 令牌只存哈希；所有读写删校验 `anon_id+token`；失败统一 404；负向安全用例进 Gate |
| 对话落库=新数据收集 | 最小化收集；删除按钮+90 天清理；日志不记正文/令牌；隐私文案同批上线；简历成稿只存本机 |
| 模板契约漂移 | 单一 JSON + semver + `/template` 唯一出口；版本不匹配 409；契约快照测试防前后端分叉 |
| qwen reasoning 不确定 | 先 spike `enable_thinking/reasoning_content`；只展示整理后的 `reasoning_summary`，不依赖原始 CoT |
| 编排 JSON 不稳 | Schema 校验 + 修复重试 1 次；连续失败 3 次降级规则式提问，不整轮报错 |
| 每轮多模型调用→延迟 | L1 规则跳过编排；orchestrator 用 turbo；extractor 流后跑；reasoning 仅 deep 轮；step 事件先行 |
| extractor 抽不稳 | 熔断：改每 3 轮批量抽取 / 退化关键词画像，coverage 标注低置信来源 |
| 访谈像查户口 | prompt 约束+人工 rubric 熔断；KB 钩子让追问有据；12 轮上限，到顶输出 gaps |
| optimize 超时(FC 限制) | `plan` + 逐 section 客户端编排；单段 p95 实测留余量；不达标缩范围或 P3 延期 |
| 滥用/成本失控 | IP/anon/session 三层限流、日 token 预算、输入输出上限、`COACH_ENABLED=0` 回退 v1 |
| 截止前替换核心链路 | 默认 v1 冻结提交；赛前只上 P0+最小访谈+P2 单模板；不达标整体回滚 v1 |
| LangGraph 依赖膨胀 | 不引入——手写轻量状态机，照抄 checkpoint 思想 |
