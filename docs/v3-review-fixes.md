# V3 审查修复说明

基线：`3026854304ac88102309f085caed908ee7f0da79`（dev/v2）。

## 会话导入鉴权契约

`X-Owner-Token` 只授权目标长期记忆，不授权读取任意访谈。

- `POST /api/v3/facts/extract`：请求体仍是 `{session_id}`，另须携带该访谈的 `X-Anon-Id` 和 `X-Session-Token`。读取访谈/调用模型及计费前验证 V2 会话凭据。缺失、错误或越权凭据统一返回 404。
- `POST /api/v3/memory/backfill`：请求头携带 `X-Owner-Token`、`X-Anon-Id`，请求体使用 `{session_ids: [...], session_tokens: {"会话 UUID": "该会话令牌"}}`，每批最多 30 个。逐会话校验，不合法项返回 `not_found`，不调用抽取器、不消耗抽取日额度。省略 `session_ids` 时仅使用所提交令牌映射中的会话，绝不根据可伪造的 `owner.anon_id` 自动抓取历史访谈。
- 前端复用现有本地访谈令牌；没有凭据的历史会话禁选，并提示在原浏览器操作。恢复长期记忆不会凭空恢复另一个浏览器的 V2 访谈令牌。
- `fact_extractor.extract_incremental` 是内部服务函数；其他调用方必须先完成 V2 会话权限校验，不能直接把外部 UUID 交给它。

## 隐私与导出

忘掉会话会分页清理该 owner 的全部事实（含软删除事实）、全部简历及历史版本中的该会话来源指针/原话证据，包含同一事实合并后的次要来源。保留其他会话证据、事实值和用户简历字段；此操作不是删除 V2 访谈本体。历史版本恢复不应重新带回已擦除的证据。

导出分页获取未软删除的事实和简历，避免被服务端 max-rows 截断或导出已删除事实。

**一致性边界：**当前 REST 多步擦除不是数据库事务；与抽取/保存并发进行时仍有竞争窗口。需要数据库事务和来源 tombstone 才能提供严格的并发删除保证。现有修复保证无并发写入时的清理闭环，不宣称生产环境已完成事务级验证。

## 手工编辑与证据

重新生成时显式保留手改叶子字段，即使模型返回的数组变短；无法恢复的路径记录在 `_meta.manual_unavailable`，不再静默丢失。手工字段不继续沿用模型给出的事实背书，显示“手工填写，未由事实证据背书”。保存手工字段时清除旧证据/事实快照，避免将旧值的来源错误归给新值。

## 恢复与停用

记忆页可使用恢复码换发并保存新 token，展示新的 token/恢复码；旧 token 和旧恢复码失效。恢复成功后即使后续状态加载失败，也应保留新凭据展示。恢复凭据不代表重新同意：停用 owner 恢复后仍停用，需显式重新开启。只有 `GET /api/v3/memory` 允许合法停用凭据查看 `enabled:false`，事实读取和抽取仍默认要求启用。

## 跨域与部署配置

FastAPI CORS 允许 `PATCH` 和 `If-Match`，FC HTTP trigger 模板同步允许 `PATCH`/`OPTIONS`。部署环境需显式提供 `V3_MEMORY_ENABLED=0`（迁移/验收前）或 `1`（经人工确认后），配置模板透传该值，不自动启用 V3。

本轮只修改代码与部署模板，不执行数据库迁移、真实模型调用或部署。离线测试不是生产数据库、浏览器 E2E 或线上验收的替代品。
